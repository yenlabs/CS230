
# The Gaming Room

## Project Overview

The Gaming Room was the client for this project. They wanted to expand their existing Android game, Draw It or Lose It, into a web-based application that could work across different platforms. The game is a drawing game and guessing game where teams compete to identify images. The software needed to support multiple games, teams, and players while making sure the names stayed unique.

## What I Did Well

I think I did well at breaking down the client's requirements and connecting them to the software design. I was able to look at areas like operating platforms, memory, storage, security, and networking and explain how they would affect the application. I also became more aware of design patterns like Singleton and thinking about how the application could grow in the future.

## How the Design Document Helped

Working through the document helped me understand the application before focusing completely on the code. It made me think about how each part of the system would work together and what the client needed. Having that plan could make the coding process easier because you have a better idea of how the application can be structured.

## What I Would Improve

If I could revise one part of my documentation, I would improve some of my technical explanations. I would make them more specific and connect them more directly to Draw It or Lose It instead of only explaining the technology in general. This would make my recommendations clearer and show why they are a good fit.

## Understanding the User's Needs

I focused on the client's need for the game to work across multiple platforms while still being secure, reliable, and easy to use. I also considered requirements like supporting multiple teams and players and preventing duplicate names. Considering the user's needs is important because the software should solve their actual problems instead of working from a technical perspective.

## My Approach to Software Design

My approach was to first understand the requirements and then break the application to smaller parts. From there, I looked at which design patterns, platforms, and technologies would work best. In future projects, I would continue using design documents, UML diagrams, design patterns, and requirement analysis because they make it easier to organize the project I am working on before getting too deep in code.
